The receiver is also documented upstream in the [awsecscontainermetricsreceiver README](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/awsecscontainermetricsreceiver).

The Amazon ECS container agent provides a method for customers to retrieve various task metadata and
[Docker stats](https://docs.docker.com/engine/api/v1.30/#operation/ContainerStats) by using
[ECS Task Metadata Endpoint](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/task-metadata-endpoint.html).
The AWS Container Observability team developed a receiver in the OpenTelemetry Collector that scrapes this endpoint and
collects container metrics (such as CPU, memory, network, and disk). Customers can enable `awsecscontainermetrics` receiver
in their OpenTelemetry configuration file to collect specific task- and container-level metrics and send the data to
desired monitoring tools such as Amazon CloudWatch.

This receiver works with [ECS Task Metadata Endpoint V4](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/task-metadata-endpoint-v4.html),
which means Amazon ECS tasks with Fargate launch type with platform version `1.4.0` or later or Amazon ECS tasks with Amazon
EC2 launch type with ECS agent version `1.39.0+`. For more information, see
[Amazon ECS Container Agent Versions](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/ecs-agent-versions.html).

## Enabling the AWS ECS Container Metrics Receiver

To enable the `awsecscontainermetrics` receiver, add the name under receiver section in the config file `(local/config.yaml)`.
By default, the receiver scrapes the ECS task metadata endpoint every 20s and collects all metrics
(For the full list of metrics, see [Available Metrics](#available-metrics)).

The following configuration collects AWS ECS resource usage metrics by using `awsecscontainermetrics` receiver and sends
them to the [CloudWatch OTLP metrics endpoint](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch-OTLPEndpoint.html)
with the `otlp_http` exporter. The `sigv4auth` extension signs the requests with the task role's credentials, so the task
role needs the `cloudwatch:PutMetricData` permission. Replace `us-west-2` with your Region.

The CloudWatch OTLP metrics endpoint requires a start time on cumulative datapoints. The receiver reports its CPU usage
time, network I/O, and storage metrics as cumulative sums without a start time, so the endpoint rejects them and the
collector logs a `Partial success response` warning. The `filter/cloudwatch` processor drops these metrics; the other
metrics are gauges, which the endpoint accepts. For the full list, see [Available Metrics](#available-metrics).

```yaml lineNumbers=true
extensions:
  sigv4auth:
    region: us-west-2
    service: monitoring

receivers:
  awsecscontainermetrics:

processors:
  filter/cloudwatch: # drop the cumulative sums, which the CloudWatch OTLP endpoint rejects
    metrics:
      exclude:
        match_type: regexp
        metric_names:
          - .*\.cpu\.usage\.(total|kernelmode|usermode|system)$
          - .*\.network\.io\.usage\..*
          - .*\.storage\.(read|write)_bytes$

exporters:
  otlp_http:
    compression: gzip
    metrics_endpoint: https://monitoring.us-west-2.amazonaws.com/v1/metrics
    auth:
      authenticator: sigv4auth

service:
  extensions: [sigv4auth]
  pipelines:
    metrics:
      receivers: [awsecscontainermetrics]
      processors: [filter/cloudwatch]
      exporters: [otlp_http]
```

To query the metrics, open **Query Studio** in the CloudWatch console and use PromQL. For example, the memory that each
task in a cluster uses:

```
{"ecs.task.memory.utilized", "@resource.aws.ecs.cluster.name"="my-cluster"}
```

For details, see [Query metrics with PromQL](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch-PromQL.html).
To get Container Insights metrics for ECS without running a collector, see
[Container Insights for Amazon ECS](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/cloudwatch-container-insights.html).

## Set Metrics Collection Interval

Customers can configure `collection_interval` under `awsecscontainermetrics` receiver to scrape and gather metrics
at a specific interval. The following example configuration will collect metrics every 40 seconds.

```yaml lineNumbers=true
extensions:
  sigv4auth:
    region: us-west-2
    service: monitoring

receivers:
  awsecscontainermetrics:
    collection_interval: 40s

processors:
  filter/cloudwatch: # drop the cumulative sums, which the CloudWatch OTLP endpoint rejects
    metrics:
      exclude:
        match_type: regexp
        metric_names:
          - .*\.cpu\.usage\.(total|kernelmode|usermode|system)$
          - .*\.network\.io\.usage\..*
          - .*\.storage\.(read|write)_bytes$

exporters:
  otlp_http:
    compression: gzip
    metrics_endpoint: https://monitoring.us-west-2.amazonaws.com/v1/metrics
    auth:
      authenticator: sigv4auth

service:
  extensions: [sigv4auth]
  pipelines:
    metrics:
      receivers: [awsecscontainermetrics]
      processors: [filter/cloudwatch]
      exporters: [otlp_http]
```

## Collect specific metrics and update metric names

The previous configuration collects all the metrics and sends them to Amazon CloudWatch using default names. Customers
can use `filter` and `metrics_transform` processors to send specific metrics and rename them respectively.

The following configuration example collects only the `ecs.task.memory.utilized` metric and renames it
to `MemoryUtilized` before sending to CloudWatch.

```yaml lineNumbers=true
extensions:
  sigv4auth:
    region: us-west-2
    service: monitoring

receivers:
  awsecscontainermetrics:

processors:
  filter:
    metrics:
      include:
        match_type: strict
        metric_names:
          - ecs.task.memory.utilized
  metrics_transform:
    transforms:
      - include: ecs.task.memory.utilized
        action: update
        new_name: MemoryUtilized

exporters:
  otlp_http:
    compression: gzip
    metrics_endpoint: https://monitoring.us-west-2.amazonaws.com/v1/metrics
    auth:
      authenticator: sigv4auth

service:
  extensions: [sigv4auth]
  pipelines:
    metrics:
      receivers: [awsecscontainermetrics]
      processors: [filter, metrics_transform]
      exporters: [otlp_http]
```

## Full configuration for task level metrics

The following example shows a full configuration to get the most useful task-level metrics. It uses the
`awsecscontainermetrics` receiver to collect all the resource usage metrics from the ECS task metadata endpoint, applies
the `filter` processor to select only 6 task-level gauges, batches them, and sends them to the CloudWatch OTLP metrics
endpoint. The resource attributes, such as `aws.ecs.cluster.name` and `aws.ecs.task.family`, stay on the metrics, so you
don't need to rename them to use them in PromQL queries.

```yaml lineNumbers=true
extensions:
  sigv4auth:
    region: us-west-2
    service: monitoring

receivers:
  awsecscontainermetrics: # collect 52 metrics

processors:
  filter: # filter metrics
    metrics:
      include:
        match_type: strict
        metric_names: # select only 6 task level gauges
          - ecs.task.memory.reserved
          - ecs.task.memory.utilized
          - ecs.task.cpu.reserved
          - ecs.task.cpu.utilized
          - ecs.task.network.rate.rx
          - ecs.task.network.rate.tx
  batch:

exporters:
  otlp_http:
    compression: gzip
    metrics_endpoint: https://monitoring.us-west-2.amazonaws.com/v1/metrics
    auth:
      authenticator: sigv4auth

service:
  extensions: [sigv4auth]
  pipelines:
    metrics:
      receivers: [awsecscontainermetrics]
      processors: [filter, batch]
      exporters: [otlp_http]
```

## Full configuration for task- and container-level metrics

The following example collects the same 6 metrics at both the task level and the container level. The `filter`
processor matches the metric names with regular expressions, so it selects both the `ecs.task.*` and the `container.*`
metrics. Container-level metrics also carry the `container.name` resource attribute.

```yaml lineNumbers=true
extensions:
  sigv4auth:
    region: us-west-2
    service: monitoring

receivers:
  awsecscontainermetrics:

processors:
  filter:
    metrics:
      include:
        match_type: regexp
        metric_names:
          - .*memory.reserved
          - .*memory.utilized
          - .*cpu.reserved
          - .*cpu.utilized
          - .*network.rate.rx
          - .*network.rate.tx
  batch:

exporters:
  otlp_http:
    compression: gzip
    metrics_endpoint: https://monitoring.us-west-2.amazonaws.com/v1/metrics
    auth:
      authenticator: sigv4auth

service:
  extensions: [sigv4auth]
  pipelines:
    metrics:
      receivers: [awsecscontainermetrics]
      processors: [filter, batch]
      exporters: [otlp_http]
```
