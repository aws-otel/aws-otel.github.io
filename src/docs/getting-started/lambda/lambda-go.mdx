There is no ADOT Lambda layer with Application Signals support for Go. To trace a Go function, instrument it with the
[OpenTelemetry Go SDK](https://opentelemetry.io/docs/languages/go/) and the
[`otellambda`](https://pkg.go.dev/go.opentelemetry.io/contrib/instrumentation/github.com/aws/aws-lambda-go/otellambda)
instrumentation, and add the ADOT Collector Lambda layer. The function sends spans to the collector, which runs as a
Lambda extension and forwards them to the Amazon CloudWatch OTLP traces endpoint.

<InfoBox
  textContent="Application Signals lists Go functions that are set up this way as services in the lambda:default environment, with latency, error, fault, and throttle metrics."
/>

<SectionSeparator />

## Prerequisites

* [Transaction Search](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch-Transaction-Search.html)
  enabled in CloudWatch. The OTLP traces endpoint requires it.
* A function that uses the `provided.al2023` runtime, on `x86_64` or `arm64`. Go functions on the `provided.al2` and
  `go1.x` runtimes need to move to `provided.al2023`; for how to build and package the `bootstrap` binary, see
  [Deploy Go Lambda functions with .zip file archives](https://docs.aws.amazon.com/lambda/latest/dg/golang-package.html).
* An execution role with the `CloudWatchLambdaApplicationSignalsExecutionRolePolicy` managed policy, which allows
  `xray:PutTraceSegments`.

## 1. Instrument the function

Add the OpenTelemetry Go SDK and the Lambda instrumentation to your module:

```console
go get github.com/aws/aws-lambda-go/lambda \
    go.opentelemetry.io/otel \
    go.opentelemetry.io/contrib/instrumentation/github.com/aws/aws-lambda-go/otellambda \
    go.opentelemetry.io/contrib/instrumentation/github.com/aws/aws-lambda-go/otellambda/xrayconfig \
    go.opentelemetry.io/contrib/propagators/aws/xray \
    go.opentelemetry.io/contrib/instrumentation/net/http/otelhttp
```

Create the tracer provider in `main()`, outside the handler, and wrap the handler with `otellambda.InstrumentHandler`.
`xrayconfig` exports spans over OTLP to the collector extension and flushes them at the end of each invocation. To trace
outgoing HTTP requests, use an `otelhttp` transport and pass the request context:

```go lineNumbers=true
package main

import (
	"context"
	"fmt"
	"net/http"

	"github.com/aws/aws-lambda-go/lambda"
	"go.opentelemetry.io/contrib/instrumentation/github.com/aws/aws-lambda-go/otellambda"
	"go.opentelemetry.io/contrib/instrumentation/github.com/aws/aws-lambda-go/otellambda/xrayconfig"
	"go.opentelemetry.io/contrib/instrumentation/net/http/otelhttp"
	"go.opentelemetry.io/contrib/propagators/aws/xray"
	"go.opentelemetry.io/otel"
)

var client = http.Client{Transport: otelhttp.NewTransport(http.DefaultTransport)}

func handler(ctx context.Context) (map[string]int, error) {
	req, err := http.NewRequestWithContext(ctx, http.MethodGet, "https://aws.amazon.com", nil)
	if err != nil {
		return nil, err
	}
	resp, err := client.Do(req)
	if err != nil {
		return nil, err
	}
	defer resp.Body.Close()
	return map[string]int{"statusCode": 200, "http_status": resp.StatusCode}, nil
}

func main() {
	ctx := context.Background()
	tp, err := xrayconfig.NewTracerProvider(ctx)
	if err != nil {
		fmt.Printf("error creating tracer provider: %v\n", err)
	}
	defer func(ctx context.Context) {
		if err := tp.Shutdown(ctx); err != nil {
			fmt.Printf("error shutting down tracer provider: %v\n", err)
		}
	}(ctx)
	otel.SetTracerProvider(tp)
	otel.SetTextMapPropagator(xray.Propagator{})

	lambda.Start(otellambda.InstrumentHandler(handler, xrayconfig.WithRecommendedOptions(tp)...))
}
```

For other libraries, such as the AWS SDK for Go and gRPC, see
[OpenTelemetry Go instrumentation](https://opentelemetry.io/docs/languages/go/instrumentation/).

## 2. Configure the collector

By default, the ADOT Collector Lambda layer exports traces with the `awsxray` exporter. To send them to the CloudWatch OTLP
traces endpoint instead, add this `collector.yaml` to your deployment package:

```yaml lineNumbers=true
extensions:
  sigv4auth:
    region: ${env:AWS_REGION}
    service: xray

receivers:
  otlp:
    protocols:
      grpc:
        endpoint: localhost:4317
      http:
        endpoint: localhost:4318

exporters:
  otlp_http:
    compression: gzip
    traces_endpoint: https://xray.${env:AWS_REGION}.amazonaws.com/v1/traces
    auth:
      authenticator: sigv4auth

service:
  extensions: [sigv4auth]
  pipelines:
    traces:
      receivers: [otlp]
      exporters: [otlp_http]
```

For other collector options, see the
[OpenTelemetry Lambda Collector configuration](https://opentelemetry.io/docs/platforms/faas/lambda-collector/).

## 3. Build and deploy

Build the function as `bootstrap` and package it with the collector configuration. For `arm64`, set `GOARCH=arm64`.

```console
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -tags lambda.norpc -o bootstrap .
zip function.zip bootstrap collector.yaml
```

Create the function with the collector layer, the `OPENTELEMETRY_COLLECTOR_CONFIG_URI` environment variable, and a
service name:

```console lineNumbers=true
aws lambda create-function --function-name <function-name> \
    --runtime provided.al2023 --handler bootstrap --architectures x86_64 \
    --zip-file fileb://function.zip --role <execution-role-arn> \
    --layers arn:aws:lambda:<region>:901920570463:layer:aws-otel-collector-amd64-ver-0-156-0:4 \
    --tracing-config Mode=Active \
    --environment 'Variables={OPENTELEMETRY_COLLECTOR_CONFIG_URI=/var/task/collector.yaml,OTEL_SERVICE_NAME=<service-name>}' \
    --region <region>
```

Set `OTEL_SERVICE_NAME`. Without it, the spans from the Go SDK have no `service.name`.

### Collector layer ARNs

Lambda layers are Regional, so use the layer in the same Region as your function. Use `amd64` for `x86_64` functions
and `arm64` for `arm64` functions.

| Supported Regions | Lambda layer ARN format | Contents |
|---|---|---|
| ap-northeast-1<br/>ap-northeast-2<br/>ap-south-1<br/>ap-southeast-1<br/>ap-southeast-2<br/>ca-central-1<br/>eu-central-1<br/>eu-north-1<br/>eu-west-1<br/>eu-west-2<br/>eu-west-3<br/>sa-east-1<br/>us-east-1<br/>us-east-2<br/>us-west-1<br/>us-west-2 | arn:aws:lambda:\<region\>:901920570463:layer:aws-otel-collector-\<architecture\>-ver-0-156-0:4 | Contains ADOT Collector v0.49.0 |

## 4. View your traces

Invoke the function, and then use Transaction Search in the CloudWatch console to find its spans. Each invocation has
a server span from `otellambda` and a client span for each outgoing request made through `otelhttp`, along with the
segments that Lambda creates when active tracing is on. Spans are stored in the `aws/spans` log group.

To remove tracing, remove the layer, the `OPENTELEMETRY_COLLECTOR_CONFIG_URI` variable, and the instrumentation code,
and turn off active tracing.
